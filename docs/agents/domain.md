# Documentação de domínio

Este repositório usa um único contexto de domínio. Antes de explorar uma funcionalidade, consultar as orientações do projeto, incluindo onboarding, arquitetura e documentação específica.

Quando existirem, ler também o `GLOSSARY.md` na raiz e as decisões aplicáveis em `docs/adr/`. Se não existirem, prosseguir sem criá-los antecipadamente.

Usar os termos definidos pelo glossário e pela documentação existente. Sinalizar conflitos com decisões arquiteturais relevantes em vez de ignorá-los.
